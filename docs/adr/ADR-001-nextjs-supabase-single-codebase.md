# ADR-001 — بنية Next.js الموحّدة (ويب + موبايل) مع Supabase

- **Status:** Accepted
- **Date:** 2026-08-15
- **Owner:** مالك المشروع
- **Reversal conditions:** إذا تجاوز حمل الكتابة حد العقدة الواحدة في Supabase، أو تطلب الموبايل تجربة أصلية معزولة (push فوري/offline معقد) تعجز عنها واجهة الويب، يُعاد تقييم الفصل (Backend منفصل / تطبيق أصلي مستقل).

## Context
المشروع (نبض المدينة) متجر إلكتروني ليبي بواجهتين: متجر ويب، وتطبيق موبايل. احتياجات الجدول الزمني والميزانية تتطلب إعادة استخدام قصوى للكود وقاعدة بيانات واحدة متزامنة بين الواجهتين مع تشغيل سريع.

## Decision
- **منصة واحدة:** Next.js 16 (App Router) بجذر واحد يخدم واجهة الويب **و** عرض الموبايل في نفس الحزمة (`#mobile` view)، ويُعبّأ كتطبيق Android عبر **Capacitor** (WebView) مع `api-bridge` يعيد توجيه `/api/*` إلى الخادم الحي داخل الـAPK.
- **قاعدة بيانات واحدة:** **Supabase (Postgres)** عبر Prisma، بمصدر حقيقة موحّد (`SUPABASE_DATABASE_URL`).
- **نشر:** Vercel (CLI + تكامل git)، والـAPK يُخدَّم من Supabase Storage.
- **حالة العميل:** Zustand، مع توحيد جلسة الويب والموبايل عبر `useUIStore` كمصدر واحد.
- **مزامنة المفضلة/الإعدادات:** الخادم مصدر الحقيقة، مع نية صريحة (POST/DELETE) بدل toggle انعكاسي.

## Alternatives Considered
| البديل | سبب الرفض |
|---|---|
| React Native أصلي كامل | تكلفة/وقت مضاعف، فريق صغير، وتكرار منطق الأعمال |
| Backend منفصل (Node/Express) + BFF | تعقيد زائد بلا حاجة حالية؛ Next API Routes تكفي |
| قاعدة SQLite محلية للنشر | لا مشاركة متعددة الأجهزة ولا متانة إنتاج |
| PostgreSQL ذاتية الاستضافة | عبء صيانة؛ Supabase توفر托管 + auth/storage |

## Consequences
**إيجابية (+):**
- إعادة استخدام كاملة للكود/logic/الاختبارات بين الويب والموبايل.
- قاعدة واحدة متزامنة تلقائياً؛ نشر واحد.
- اختبارات موحّدة (29 اختباراً حالياً) تغطي الطرفين.
- تكلفة تشغيل منخفضة (Vercel + Supabase مجانيان لحد كبير).

**سلبية (−):**
- الـAPK WebView يفتقر لقدرات أصلية (push عميق، أداء ثقيل) — مقبول حالياً.
- اقتران الواجهتين: تغيير الويب يؤثر على الموبايل والعكس (يحتاج عناية بالمزامنة).
- قيود Supabase (connection_limit=1 في URL الحالي) تتطلب ضبط pool.
- لا فصل قابل للتوسع الأفقي للخدمات بلا إعادة هيكلة.
